USERNAME FORGE CHECKER — RENDER DEPLOYMENT

FILES
- main.py: FastAPI service that asks Telegram whether a username can be assigned to the logged-in account.
- make_session.py: creates a Telethon StringSession on your own device.
- requirements.txt: Python dependencies.
- render.yaml: Render Blueprint configuration.

IMPORTANT
- This is a checker, not a reservation system. A username can be claimed by someone else immediately after checking.
- Use it for occasional checks only. Telegram may rate-limit repeated checks.
- Telegram username checks are performed using your own Telegram user account session.
- Never share your Telegram OTP, 2-step password, API_HASH, SESSION_STRING, or SERVICE_KEY.
- A SESSION_STRING can grant access to your Telegram account. Keep it private.
- If you previously exposed a BotFather token, revoke it in @BotFather and replace it in your bot configuration.

STEP 1 — Telegram API credentials
1. On your own device, open https://my.telegram.org
2. Sign in and open API development tools.
3. Create an application and keep API_ID and API_HASH private.

STEP 2 — Create SESSION_STRING on Android
1. Install Pydroid 3 or Termux.
2. In its terminal, run: pip install -r requirements.txt
   (If you only want to generate the session, run: pip install "Telethon>=1.41,<2")
3. Run: python make_session.py
4. Enter API_ID, API_HASH, your phone number, Telegram login code, and 2-step password if asked.
5. Copy the printed SESSION_STRING directly into your own Render Environment. Do not send it in chat or upload it to GitHub.

STEP 3 — Upload files to GitHub
1. Create a PRIVATE repository named username-forge-checker.
2. Extract this ZIP on Android.
3. Open the extracted folder and upload the four files inside it to the ROOT of the repository:
   main.py, make_session.py, requirements.txt, render.yaml
4. Do not upload the ZIP itself. Do not upload any file containing secrets.

STEP 4 — Deploy on Render
1. Open https://dashboard.render.com
2. Choose New > Blueprint.
3. Connect the private GitHub repository username-forge-checker.
4. Render reads render.yaml and creates the web service.
5. In the service Environment settings, set API_ID, API_HASH, and SESSION_STRING.
6. Keep SERVICE_KEY generated by Render private. If Render asks you to provide it, generate a long random secret and store it privately.
7. Save changes and redeploy.
8. When deploy succeeds, open https://YOUR-SERVICE.onrender.com/health. Expected response: {"ok":true}

STEP 5 — Connect TBC
In your TBC bot's .env command/config, set:
CHECKER_URL = "https://YOUR-SERVICE.onrender.com"
CHECKER_KEY = "YOUR_SERVICE_KEY"

Example TPY request (adapt to your existing /gen flow):
response = HTTP.post(
    CHECKER_URL + "/check",
    json={"key": CHECKER_KEY, "username": candidate}
)
data = response.json()
if response.status_code == 200 and data.get("verified") and data.get("available"):
    # candidate was verified available at check time
    pass
else:
    # skip it; for 429/503 tell the user to retry later
    pass

LIMITATIONS
- Render Free web services sleep after a period without inbound requests and may take time to wake. This is not guaranteed 24/7 hosting.
- Availability is only true at the instant Telegram checks it; another user can claim the username right after.
- Do not use bulk scanning or rapid repeated requests. Telegram rate limits may apply.
